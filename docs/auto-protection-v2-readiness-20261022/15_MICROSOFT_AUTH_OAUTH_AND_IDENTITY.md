# Microsoft auth, OAuth and identity — supported vs unsupported

- Admin consent uses tenant-specific Microsoft v2 authority URL, `scope=https://graph.microsoft.com/.default`, HTTPS redirect URI validation, hashed one-time expiring state bound to initiating AccessProof admin/source/tenant/drive/root. Graph app token acquisition targets the fixed tenant token endpoint, and refresh checks endpoint trust.
- Entra stable user/group provider IDs must be checked; email is metadata, not authorization proof. Cross-OIDC Guard mapping stores verified issuer, subject and tenant and links them to source provider identities. One Microsoft Entra tenant per AccessProof organization remains enforced. Unsupported guest/siteUser/native-group identities never implicitly resolve by email or internal SQL primary key.
- SharePoint REST `GetUserEffectivePermissions` requires a verified SharePoint LoginName and a separately obtained **SharePoint-audience** access token. Graph-audience `/.default` token cannot be swapped into SharePoint REST and considered a success.
- Existing read-only SharePoint list-item probe rejects malformed sites, list item IDs, unsafe URLs and invalid masks. It does **not** verify consented real SharePoint permissions, publish Guard ALLOW or certify link possession/inheritance.
- A new `source_effective_certifications` record is only accepted with correct long HMAC key, exact bounded source/profile/tenant/drive/root/site/list (or OneDrive owner), version, evidence digest and unexpired signed proof. No ordinary user/customer-admin endpoint issues one; currently NO-GO for both Microsoft sources.
